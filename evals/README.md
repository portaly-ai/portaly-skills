# Skill evaluation model

This repository separates deterministic protocol checks from agent behavior
evaluation. A passing self-sign/self-verify test is not enough for callback v1:
the sender and receiver can share the same ordering bug.

## Deterministic conformance

Run all committed adapters against signatures generated by the production
callback contract, verify negative and fail-closed cases, and enforce parity
between the independently installable payment and product skills:

```bash
node evals/run-conformance.mjs --runtime all
```

No real API key, callback secret, customer payload, database, application or
Portaly network call, or AI model is required. The fixture secret and data are
synthetic.

## Fresh-agent behavior eval

`evals/evals.json` is a replayable prompt corpus for skill-creator or another
agent evaluator. Run every prompt in a clean workspace with the candidate skill
and with the previous released skill. Grade observable repository evidence and
test output, not prose confidence. Keep evaluator workspaces and result bundles
under the gitignored `evals/workspaces/` and `evals/results/` directories.

The prompt corpus is data, not an automatic test runner. Executing it requires
a separately authenticated model runner and consumes model-provider usage or
budget. Keep that lane manual and require explicit approval before running it.

## Consumer and sandbox lanes

A separate consumer fixture application should import the candidate vectors and
run its actual callback verifier as a regression test. A second clean consumer
workspace can replay an end-to-end integration prompt to measure whether a
fresh agent selects the correct runtime route and produces code that passes the
same vectors.

Real test-mode checkout and callback delivery require approved credentials and
external state. Keep that lane manual or scheduled, use environment secrets,
and do not make it a pull-request prerequisite until ownership, teardown, and
flakiness policy are defined.
